# cv-qiaa-eval

Проверка статьи «Continuous-Variable Quantum-Inspired Attention Architecture (CV-QIAA)» и её приложения «Wave-Transformer» (Gemini, Ana d'Elior, Yuri Barzov, 3 ноября 2026). Оригиналы лежат в [`paper/`](paper/).

## Вывод

Заявления статьи не подтверждаются. Обученный на текстах CV-QIAA предсказывает хуже обычного attention, учится в 17 раз дольше и занимает в 7–8 раз больше памяти, а не на 50% меньше. Код из статьи без исправлений не запускается. После исправления на CPU он с первого шага даёт NaN в градиентах. Позиционная часть устроена так, что «локальная» голова после ~100-го символа не видит соседей, а «широкая» сильнее всего смотрит на начало текста.

## Результаты

### 1. Код из статьи не запускается

| Ошибка | Где | Что происходит |
|---|---|---|
| `K.mtheH` | attention, обе статьи | `AttributeError`: такого атрибута нет, нужен `K.mH` |
| `targets.view(-1)` | демо в «Wave-Transformer» | `RuntimeError`: `targets` — срез, нужен `reshape` |

[`src/paper_wavellm.py`](src/paper_wavellm.py) — код из статьи без изменений, [`src/wavellm_fixed.py`](src/wavellm_fixed.py) — он же с двумя исправлениями (генерирует [`scripts/make_fixed.sh`](scripts/make_fixed.sh), `diff` показывает ровно две строки кода). Больше в коде статьи ничего не менялось.

### 2. Демо из статьи не проверяет attention

Демо учит модель 5 шагов на 4 случайных последовательностях по 12 чисел, и статья называет падение loss доказательством работоспособности. Тот же прогон с отключённым attention тоже даёт падение: модель просто запоминает 44 числа.

| Attention | Loss по шагам 1–5 |
|---|---|
| CV-QIAA | 2.41 → 2.05 → 1.78 → 1.60 → 1.44 |
| обычный (softmax) | 2.56 → 2.17 → 1.92 → 1.71 → 1.51 |
| нет | 2.46 → 2.10 → 1.92 → 1.80 → 1.72 |

### 3. На реальном тексте CV-QIAA хуже обычного attention

TinyStories посимвольно, одна и та же модель (4 слоя, d_model 128, 4 головы, контекст 128, 3000 шагов, batch 32), меняется только attention:

| Вариант | Что это | Запусков | Val loss | Бит на символ | Время обучения |
|---|---|---|---|---|---|
| softmax | обычный attention с RoPE | 3 | **0.974 ± 0.003** | 1.41 | 2.2 мин |
| born | обычный attention, softmax заменён на правило Борна из статьи | 3 | 1.034 ± 0.001 | 1.49 | 2.8 мин |
| cvqiaa | слой из статьи как есть | 2 | 1.284 ± 0.035 | 1.85 | 37.6 мин |
| none | attention выключен | 3 | 2.298 | 3.32 | 1.2 мин |

- **CV-QIAA использует контекст**: он заметно лучше модели без attention. Но по качеству он отстаёт от обычного attention, а каждый шаг обучения в 17 раз медленнее.
- **Замена softmax на правило Борна сама по себе немного ухудшает результат** (born против softmax). Значит, главная идея статьи не даёт выигрыша даже отдельно от остальной конструкции.
- В CV-QIAA меньше параметров attention (181 тыс. против 263 тыс.), но этой разницей отставание не объясняется: born с тем же числом параметров, что у softmax, отстаёт на 0.06, а CV-QIAA — на 0.31.

Образцы текста от «Once upon a time» лежат в [`results/summary.md`](results/summary.md). У softmax и born — связные предложения, у CV-QIAA — обрывки слов.

### 4. Памяти и времени нужно больше, а не меньше

Один слой attention, batch 4, прямой и обратный проход на Apple M1 Pro (MPS):

| Контекст | softmax | born | CV-QIAA |
|---|---|---|---|
| 256 | 42 мс, 7 МБ | 46 мс, 15 МБ | 331 мс, 46 МБ |
| 512 | 113 мс, 21 МБ | 115 мс, 54 МБ | 413 мс, 158 МБ |
| 1024 | 127 мс, 74 МБ | 150 мс, 206 МБ | 1371 мс, 580 МБ |

МБ — память, которую слой держит после прямого прохода для обратного. Статья обещает экономию памяти 50%. На деле CV-QIAA для каждой пары токенов считает интеграл по сетке из 64 точек, поэтому у него промежуточные тензоры размером T×T×64 сверх обычной матрицы T×T.

### 5. Позиционная часть ведёт себя не так, как описано

Статья пишет, что узкая голова (σ₀ = 0.5) смотрит на соседние символы, а широкая (σ₀ = 4) — на тему текста. В коде позиции равны 0.1 × номер символа, а «холст» — сетка от −5 до 5. При контексте 128 позиции доходят до 12.7 и выходят за сетку. Расчёт в [`scripts/diagnose.py`](scripts/diagnose.py):

- **Узкая голова** с 101-го символа не видит саму себя, а у последнего символа вес соседей ровно 0. Самый сильный ключ у 127-го символа находится на 74 символа назад.
- **Широкая голова** у 127-го символа даёт первому символу вес в 22 раза больше, чем самому себе. Чем дальше ключ, тем больше вес. Это обратно тому, что утверждает статья.

Формула в статье, `exp(-(s_Q - s_K)² / 4σ(t)²)`, такого поведения не даёт. Код считает другое: интеграл по ограниченной сетке.

### 6. NaN на CPU

Когда вес пары уходит в машинный ноль, `torch.abs` от комплексного нуля даёт NaN в градиенте. На CPU после первого шага NaN у 139 из 172 тензоров параметров, и обучение невозможно. На MPS (Apple GPU) этот случай даёт 0, поэтому обучение выше шло на MPS. На CUDA не проверялось. Исправляется в одну строку: `real**2 + imag**2` вместо `abs()**2`. Именно так записана формула в самой статье.

### Что не проверялось

- Фотонная реализация (Annex C). Ни чипа, ни моделирования в статье нет, проверять нечего.
- Длинный контекст и большие модели. Здесь модели по ~0.8 млн параметров, обучение на 17 млн символов, 3000 шагов. На больших масштабах соотношение может измениться, но статья не приводит для этого никаких данных.
- Работа на CUDA.

## Как воспроизвести

Подготовка (Python 3.13, macOS с Apple Silicon; на другой машине обучение пойдёт на CPU, где CV-QIAA даёт NaN):

```bash
python3.13 -m venv .venv && .venv/bin/pip install -r requirements.txt
mkdir -p data && curl -L -o data/TinyStories-valid.txt https://huggingface.co/datasets/roneneldan/TinyStories/resolve/main/TinyStories-valid.txt
```

1. `.venv/bin/python src/paper_wavellm.py` → `AttributeError: 'Tensor' object has no attribute 'mtheH'`.
2. `scripts/make_fixed.sh && .venv/bin/python src/wavellm_fixed.py` → 5 строк с падающим loss, последняя `1.4435`.
3. `.venv/bin/python scripts/diagnose.py` → таблица демо из раздела 2, расчёт перекрытий из раздела 5, строка `CPU: 139 of 172 parameter tensors have NaN gradient`. Результат пишется в `results/diagnose.json`.
4. `.venv/bin/python scripts/bench.py` (~2 мин) → таблица раздела 4 в `results/bench.json`. Время на малых контекстах колеблется от запуска к запуску, память стабильна.
5. `scripts/run_all.sh` (~1.5 часа на M1 Pro; почти всё время занимает CV-QIAA) → `results/train-*.json`, затем `.venv/bin/python scripts/summarize.py` → таблица раздела 3 в `results/summary.md`. Значения val loss должны совпасть с точностью ±0.01 для softmax и born; у CV-QIAA разброс больше (±0.04).

## Устройство

- `src/models.py` — общая модель (каркас WaveLLM из статьи) и четыре варианта attention.
- `scripts/train.py` — обучение одного варианта: посимвольные токены, 90% текста на обучение, 10% на проверку, AdamW, lr 1e-3 с прогревом и косинусом, обрезка градиента 1.0. Проверка на одних и тех же 50 батчах для всех запусков.
